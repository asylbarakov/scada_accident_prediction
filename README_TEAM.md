# SCADA Predictive Maintenance · передача команде KEGOC

## Назначение

Исследовательский MVP проверяет, можно ли по истории SCADA заранее выделить окна перед отказами ветровых турбин. **Failure Prediction H7** — оценка риска зарегистрированного отказа в следующие 7 суток. Для точки в момент `t` с подтверждённым якорем отказа `f` положительная метка означает `t < f ≤ t + 7 суток`. Отрицательные метки формируются в проверенных нормальных сегментах при наблюдаемом горизонте. Неоднозначные и неполные интервалы исключаются из оценки.

Эксперимент использует **CARE to Compare v6, Wind Farm A**. Это анонимизированная выборка из 22 файлов событий пяти наземных турбин в Португалии. Данные подходят для проверки методики и демонстрации интерфейса. Оборудование, частоты отказов и эксплуатационные режимы KEGOC не исследовались. [Источник CARE v6](https://zenodo.org/records/15846963) · [Атрибуция и условия распространения](DATA_LICENSES.md)

- **Logistic Regression** — линейный базовый вариант, с которым можно сравнить результат более сложной модели. В сохранённый pipeline входят импутация и масштабирование.
- **LightGBM** — бустинг по деревьям для проверки нелинейных зависимостей между признаками. В сохранённый pipeline входят импутация и модель из 250 деревьев.
- **Gain** показывает вклад разбиений по признаку в функцию потерь при обучении LightGBM. **TreeSHAP** раскладывает оценку конкретного прогноза на базовое значение и вклады признаков в шкале log-odds. Global SHAP агрегирует абсолютные вклады по тесту. Для важности датчика вклады его признаков суммируются до агрегирования. SHAP объясняет поведение модели. Установление физической причины отказа требует отдельных данных.

## Что реализовано

1. Адресная загрузка Wind Farm A из исходного ZIP Zenodo и аудит доступности, структуры, метаданных событий и каналов. Можно использовать уже распакованные оригиналы. [Аудит источника](docs/local_data_gate.md)
2. Подтверждение якорей по `event_end` и идентификатору строки, сверка повторов по датам и отпечаткам рядов, учёт сдвинутых копий. Пересекающиеся файлы сгруппированы, конфликтующие метки цензурируются. Связанное событие 51/72 учитывается как один тестовый эпизод. Признаки и отбор точек не используют `status_type_id`. [Аудит H7](docs/care_h7_audit.md)
3. Расчёт 210 признаков из 10 физических каналов. Используются последние доступные показания и статистики окон 1, 6, 24 и 168 часов. Шаг сырых измерений 10 минут, задержка доступности один шаг, минимальная история 24 часа, прогнозы почасовые. Предобработка моделей обучалась только на train.
4. Разделение по непересекающимся турбинам и связанным группам телеметрии. Проверка разведения выполняется и на истории признаков. Повторный data gate проверил 1 196 747 сырых строк и допустил обучение H7.
5. Обучение на train, выбор порогов на validation при бюджете 2 ложных предупреждения на турбину-месяц. Test использовался для отложенной оценки. Сохранены оба `pipeline.joblib`, `inference.json`, раздельные прогнозы и событийные метрики. Повторная загрузка воспроизводит score и флаги.
6. Экспорт gain, глобального и локального TreeSHAP, ранга физических датчиков и графиков SCADA. Глобальный TreeSHAP рассчитан по 644 тестовым точкам. Сохранены вклады для пяти примеров. Dashboard также рассчитывает локальное объяснение любой сохранённой точки при наличии строки признаков.
7. Четыре раздела Streamlit. **Overview** показывает список турбин, выбор файла, предупреждения и итоговую сводку. **SCADA Monitoring** позволяет сравнить два физических канала. **Failure Prediction** отображает сохранённые score, пороги, первое предупреждение и отметку CARE. **Model Explainability** показывает gain, глобальный и локальный SHAP и временной ряд выбранного датчика. В режиме воспроизведения телеметрия учитывает задержку доступности, а прогнозы и отметки отказов появляются к выбранному срезу UTC.

## Результаты сохранённого эксперимента

| Выборка | Турбины | Почасовые точки | Положительные / отрицательные | Эпизоды отказов |
| --- | --- | ---: | ---: | ---: |
| Train | 0, 10 | 1 508 | 861 / 647 | 6 |
| Validation | 11, 13 | 829 | 449 / 380 | 3 |
| Test | 21 | 644 | 311 / 333 | 2 |

| Модель | Выборка | PR-AUC (AP) | ROC-AUC | Обнаружено отказов | Ложные предупреждения / турбина-месяц | Медиана до отказа |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Logistic Regression | Validation | 0,8094 | 0,7122 | 2/3 | 0 | 66,83 ч |
| LightGBM | Validation | 0,4888 | 0,3918 | 0/3 | 0 | — |
| Logistic Regression | Test | 0,9067 | 0,9136 | 1/2 | 0 | 168 ч |
| LightGBM | Test | 0,7405 | 0,8363 | 0/2 | 0 | — |

Порог Logistic Regression — `0.9999999614086562`. На тесте обнаружен отказ гидравлической группы в событии 22 за 168 часов. Отказ редуктора 51/72 пропущен. Порог LightGBM — `1.0000000000000002`. Любой проверенный порог, который давал хотя бы одно обнаружение на validation, превышал заданный бюджет ложных тревог. Сохранённый порог выключает оповещения, и LightGBM пропустил оба тестовых отказа.

Тест содержит два эпизода одной турбины. Один эпизод меняет событийный recall на 50 процентных пунктов. Ноль наблюдённых ложных тревог получен на 333 часах отрицательной экспозиции, около 0,456 турбина-месяца из одного нормального сегмента. Окна коррелированы. AP и ROC-AUC характеризуют ранжирование и рассчитываются независимо от порога. Score обеих моделей **некалиброваны** и не выражают вероятность отказа. H30 в этом CARE-эксперименте отсутствует. Лидирующий вклад температуры воздуха может отражать сезонность и подбор окон. **Кеш Full.** `features.parquet` содержит признаки, ключи, метки и готовность истории. `scada.parquet` — извлечённые физические показания. `labels.parquet` хранит причины включения и исключения. `observation_lineage.parquet` и `overlaps.json` фиксируют повторы. `feature_map.json` связывает признаки с каналами и единицами. `coverage.json` фиксирует покрытие и совместимость конфигурации.

**Артефакты Dashboard.** На старте нужны `training/config.json`, `metrics.json`, `preparation_coverage.json`, оба `inference.json` и по два файла прогнозов для validation и test. Для SCADA используются CSV, для теста предусмотрен запасной `h7/lightgbm/risk_sensor_history.parquet` с пятью датчиками. Глобальные объяснения читаются из `feature_importance.csv` и `sensor_importance.csv`. Для динамического Local SHAP нужны оба `pipeline.joblib` и `features.parquet`. В `local_shap.csv` лежат пять архивных объяснений. PNG, data gate, ноутбуки, исходная история признаков и датчики сверх выбранных каналов нужны для отчётов, исследований или повторного обучения.

**Demo.** В 22 файлах сохранены реальные строки раздела `prediction`, 10 каналов и поля идентификации. Кеш сокращён до 1 473 точек с архивными прогнозами и 210 признаков. Demo поддерживает все четыре страницы, динамический SHAP на validation и test и показания обучающих турбин. Архивных score для train нет. Кеш Demo предназначен для инференса Dashboard.

**Full.** Включены 22 неизменённых исходных CSV и оба файла метаданных Wind Farm A, актуальный кеш CARE H7, отчёты, исходники, конфигурации, ноутбуки и тесты. Полный архив Zenodo размером 5,5 ГБ и ветропарки B/C для повторения H7 не требуются. Внешние исходники EDP, их кеши, прежний дублирующий кеш CARE и сгенерированные входы дымовых тестов исключены. Повторение EDP зависит от отдельно полученных данных. [Аудит EDP](docs/edp_data_audit.md)

## Установка и запуск в Windows

1. Распакуйте ZIP в отдельный каталог, например `C:\Projects\scada-demo` или `C:\Projects\scada-full`. Откройте PowerShell в папке с `app.py`. Можно использовать `Expand-Archive -LiteralPath .\scada-pdm-mvp-demo.zip -DestinationPath .\scada-demo`.
2. Проверьте `py -0p` и `py -3.14 --version`. Проверенная версия — **CPython 3.14.6 x64**. Если команда `py` отсутствует, выполните `python --version` и используйте `python -m venv .venv` после проверки версии.
3. Создайте окружение. Установка использует PyPI или корпоративное зеркало. Датасеты при запуске уже находятся в архиве.

   ```powershell
   py -3.14 -m venv .venv
   $python = '.\.venv\Scripts\python.exe'
   & $python -m pip install -r requirements-dashboard.txt -c requirements-windows-lock.txt
   & $python -m pip check
   & $python -m streamlit run app.py
   ```

4. Откройте [http://localhost:8501](http://localhost:8501). Если порт занят, передайте `--server.port 8502` и используйте порт 8502. Остановить запуск можно клавишами **Ctrl+C**.
5. Откройте **Overview** и проверьте турбину 21, событие 22. В **SCADA Monitoring** должны появиться реальные графики. В **Failure Prediction** проверьте сохранённое предупреждение Logistic Regression и отключённые порогом оповещения LightGBM. В **Model Explainability → Локальный SHAP** выберите момент прогноза. Подтверждение о воспроизведении score означает, что загрузились обе модели, их предобработка и кеш.
6. Автоматическая проверка поставки `& $python -m scripts.verify_distribution` загружает оба pipeline, сверяет score и флаги по всем архивным точкам, проверяет SCADA и открывает все четыре страницы через AppTest.

| Проверенные основные зависимости | Версия |
| --- | --- |
| Streamlit · Plotly | 1.53.1 · 6.5.0 |
| LightGBM · scikit-learn · joblib | 4.6.0 · 1.8.0 · 1.5.3 |
| NumPy · pandas · SciPy · PyArrow | 2.3.5 · 2.3.3 · 1.16.3 · 23.0.1 |
| Matplotlib · OpenPyXL | 3.10.8 · 3.1.5 |

Полный набор закреплённых транзитивных версий Windows находится в [requirements-windows-lock.txt](requirements-windows-lock.txt). В приложении используется встроенный TreeSHAP LightGBM. Отдельный пакет `shap` не требуется.

| Ситуация | Что проверить |
| --- | --- |
| `py`, `python` или `streamlit` отсутствуют в PATH | Проверьте установленный интерпретатор через `py -0p` или `Get-Command python`. Используйте прямой вызов `.venv\Scripts\python.exe -m streamlit`. Он также работает при запрещённой политикой активации `Activate.ps1`. |
| `No matching distribution` или зависимость пытается собираться из исходников | Проверьте архитектуру `& $python -c "import struct; print(struct.calcsize('P')*8)"`. Для проверенного набора ожидается 64. Проверьте доступ зеркала к указанным версиям и колёсам CPython 3.14 для Windows x64. |
| `DLL load failed` | Проверьте x64 Python и зависимости через `pip check`. Если сообщение указывает на DLL среды Microsoft C++, проверьте наличие принятого в вашей среде Visual C++ Redistributable x64. |
| Не найдены прогнозы, SCADA или кеш моделей | Запустите из распакованного каталога и проверьте структуру ZIP. При переносе данных `SCADA_DASHBOARD_RUN` указывает на каталог запуска, содержащий `training/`, `SCADA_DASHBOARD_RAW` — на каталог Wind Farm A, `SCADA_DASHBOARD_FEATURES` — на файл Parquet с признаками. Старые значения этих переменных могут указывать на другую копию. |
| Ошибка загрузки `joblib` или score расходятся с архивом | Сверьте версии с файлом ограничений и убедитесь, что кеш, pipeline и прогнозы относятся к одному запуску. Загружайте `joblib` только из доверенной поставки, сверяя SHA-256 ZIP. |

Интернет для установки Python-пакетов можно заменить заранее собранным зеркалом колёс. С установленными пакетами запуск использует локальные файлы. Поставки содержат файлы зависимостей, колёса в ZIP не включены.

## Разработчикам · повторение CARE H7 из Full

Работайте в корне Full. Используйте то же окружение и оставьте архивный прогон и конфигурацию эталоном. Для другого опыта скопируйте `configs/care_h7.json` под новым именем и меняйте `raw_dir`, `asset_splits`, список каналов, окна, пороговый бюджет, seed и параметры LightGBM в копии. Изменение подготовки требует нового кеша и повторного data gate.

```powershell
$python = '.\.venv\Scripts\python.exe'
$run = "results/care_h7_repeat_$(Get-Date -Format yyyyMMdd_HHmmss)"
$cache = "$run/cache"
& $python -m unittest discover -s tests -v
if ($LASTEXITCODE -ne 0) { throw 'Tests failed' }
& $python -m scada_pdm.cli prepare --config configs/care_h7.json --cache $cache
if ($LASTEXITCODE -ne 0) { throw 'Preparation failed' }
& $python -m scada_pdm.cli train --config configs/care_h7.json --cache $cache --output "$run/data_gate" --audit-only
if ($LASTEXITCODE -ne 0) { throw 'Data gate failed' }
$gate = Get-Content -Raw "$run/data_gate/metrics.json" | ConvertFrom-Json
if ($gate.horizons.h7.status -ne 'eligible') { throw 'H7 is ineligible' }
# Только при намеренном повторении обучения.
& $python -m scada_pdm.cli train --config configs/care_h7.json --cache $cache --output "$run/training"
if ($LASTEXITCODE -ne 0) { throw 'Training failed' }
& $python -m scada_pdm.cli plot-scada --run "$run/training"
```

Чтобы пропустить подготовку при той же конфигурации, укажите `cache/care_h7_v6` в `$cache` и начните с data gate. Если исходные данные были перемещены или исключены при копировании, команда `& $python scripts/fetch_care_a.py --output data` загружает только Wind Farm A по HTTP Range. При отсутствии поддержки Range скачайте официальный ZIP и извлеките его подкаталог `CARE_To_Compare/Wind Farm A` в `data/`. Для Colab используйте [CARE_H7_Training_Colab.ipynb](notebooks/CARE_H7_Training_Colab.ipynb) и инструкции [README](README.md#care-h7-в-google-colab).

Команда `& $python -m scripts.build_distribution` из исходного проекта формирует оба ZIP и манифест в `dist/`. Проверка переносимости хранится рядом с архивами. Для работы команды используйте Full и сохраняйте отчёты следующих опытов в новых каталогах.
