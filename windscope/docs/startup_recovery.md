# Восстановление WindScope после остановки сервисов

17 ноября 2026 года, Asia/Qyzylorda.

## Причина наблюдавшейся недоступности

При диагностике PostgreSQL, API и XGBoost-сервис находились в состоянии `Exited (255)`. Их время завершения совпало: `2026-11-17 04:57:04 UTC`. У всех трёх контейнеров была политика перезапуска `no`.

Интерфейс и H7-сервис уже работали, а worker циклически перезапускался. Frontend регистрировал `getaddrinfo ENOTFOUND api`, worker — ошибку разрешения имени PostgreSQL. Сам по себе работающий интерфейс или ответ H7 healthcheck не означает готовность всего приложения.

Также воспроизведён отдельный дефект интерфейса: после первой неудачной загрузки API инициализация списка сценариев и сессии не повторялась. Периодическое обновление карточек могло вернуть часть данных, но управление replay оставалось в состоянии «Загрузка сессии…».

## Исправление

- В `docker-compose.yml` добавлена политика `restart: unless-stopped` для PostgreSQL, API и исходного ML-сервиса. Все шесть постоянных сервисов теперь имеют одинаковую политику. Одноразовый `init` по-прежнему не перезапускается постоянно.
- Полный набор сервисов восстановлен через `docker compose up -d --no-build`. База использует прежний volume; данные и история не удалялись.
- `frontend/src/lib/bootstrap-recovery.mjs` повторяет неуспешное чтение API с увеличением задержки до пяти секунд. AbortSignal отменяет ожидание и не позволяет применить запоздалые данные после ухода из сессии.
- В `useWindScope.ts` повторяются как первоначальная загрузка приложения, так и загрузка выбранной сессии. После успеха сообщение о недоступности убирается, подключается WebSocket.

## Проверка

- Состояние всех шести постоянных контейнеров проверено через Docker inspect: `running`, политика `unless-stopped`.
- 34 backend-теста и 7 frontend-тестов прошли; три новых теста проверяют восстановление API, отмену повторов и отклонение позднего ответа.
- Production-сборка Next.js и TypeScript завершились успешно.
- Девять контрольных отрезков H7 повторно прошли live API/worker/WebSocket-проверку после восстановления. Прогнозы совпали с архивом; [результат](../artifacts/recovery/h7_after_restart.json).
- В браузере API был намеренно ненадолго остановлен. После reload интерфейс показал сообщение о повторном подключении. Затем API был запущен; **без дополнительного reload** появились сценарии, выбранная сессия, статус «Подключено» и сохранённый H7-прогноз.

## Эксплуатационные ограничения

Docker Desktop должен быть запущен. `unless-stopped` не запускает контейнер, который пользователь намеренно остановил. Для полного запуска из корня проекта используйте `docker compose up -d` или `./scripts/start_app.ps1`.

Replay, прерванный перезапуском worker, восстанавливается на паузе; его нужно продолжить кнопкой «Продолжить». Завершённый replay требует «Сбросить replay» перед новым запуском. Эти состояния не означают отказ модели.
